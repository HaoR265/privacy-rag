# 已集成的等价算子优化

计算保持锁定模型及修订、层数、固定输入输出预算、定点尺度和 floor 顺序。GPU 处理本方份额或密文，不通过重构秘密执行明文模型。这里介绍已经实现的路径和选择依据，不把局部性能观测作为完整问答耗时。

## 采用的路径

| 运算 | 当前实现与适用范围 | 代码入口（相对 implementation_v1） |
|---|---|---|
| 私有 Token 查表 | 密文及打包状态驻留设备，双坐标有界流水；只有显式线程安全的权重读取器使用工作线程 | `native/src/bfv_token_batch.inc`、`native/src/token_coordinate_queue.hpp` |
| Token 本方环内积及 BFV 精确缩放 | 单槽1024维、四槽2048维使用 GPU；其余公开形状保留本方 CPU 计算。无符号整数模运算与精确高低位缩放保持原数值语义 | `experiments/resident_token_gpu/` |
| BFV 矩阵 | GPU NTT、选择性系数回传及多输出组流水；适用形状使用已有逆向打包 | `native/src/bfv_matrix.inc`、`experiments/matrix_gpu/` |
| 矩阵输入加密及返回零密文 | 返回零密文的确定性算术使用 GPU；输入加密仅在公开 QK/PV 形状采用，并在一次逻辑操作内复用对象。新鲜随机材料保持独立 | `native/gpu/enc0/`、`native/src/batch_matrix.inc` |
| 客户端返回密文相位 | 公开 QK 形状采用 GPU NTT—秘密密钥乘积—逆 NTT；PV和小形状保留 CPU | `native/gpu/client_phase/` |
| SiLU 混淆电路 | 公开批量2048～6144使用分段流式 GPU 后端；其他批量使用原 CPU 电路。双方角色、门表及标签语义不变 | `native/gpu/silu_stream/`、`native/src/silu_gpu_bridge.cpp` |
| 独热掩码 | bits=1路径批量生成所需随机掩码；不扩大为所有 OT 的 GPU 化 | `native/src/secure_ops.cpp` |

QK 表示查询向量与键向量的注意力点积，PV 表示注意力概率与值向量的乘积。本次输入加密分派采用矩阵形状 `(行数,内积长度,列数)=(16,128,1280)` 与 `(16,1280,128)`；客户端相位仅采用前者。设备对象在一次公开操作内复用，不跨会话复用一次性材料。

此前已集成的精确 SiLU 仿射表达、范围/截断融合、16行 SwiGLU 批处理、矩阵三元组组织和 BFV 63 AND 解码继续保留。全部 GPU 路径由显式构建选项启用；选中路径遇到设备错误不得暗中切换到 CPU。

## 明确保留的 CPU 工作

| 工作 | 保留理由 |
|---|---|
| Token 输入密文初始化 NTT | 每次 API 只执行一次；独立诊断单槽约51.54ms、四槽约198.55ms，相比约11/41秒调用量级较小。未测试这段的 GPU 替代，不能声称 GPU 必然更慢。权重 NTT 已在 GPU |
| Token 输入公钥加密 | 比较的每API独立GPU构造单槽目标阶段慢约30.64%；四槽局部加密改善约18.71%，但两轮完整进程变化为−0.2389%与+0.06646%，合并约−0.08672%，不足以支持增加该构造的生命周期成本 |
| Token 返回相位、返回 Enc(0) | 所比较 GPU 构造未带来值得采用的完整调用净收益，保留当前 CPU 实现 |
| 范围检查及普通 BFV 解码 | 三段 Range/Floor12Range GPU 构造在128、2048、6144规模均退化；普通63门解码GPU在所测三形状慢约4.89%～20.20%。只排除这些具体构造，不外推全部非线性电路 |
| 随机材料、权重读取校验、TLS、账本和控制逻辑 | 保持本地职责与材料新鲜性；读取器包含索引、分配和拷贝，并与 GPU 重叠。等待时间不能直接视为可迁移的 CPU 计算 |

## 性能和正确性证据范围

本方环内积及缩放采用 CPU/GPU/GPU/CPU 顺序比较，每模式两次。单槽1024维完整进程均值11.1370→11.0265秒，四槽2048维41.1882→40.8958秒，分别约改善0.99%与0.71%；新增设备分配约1.25MB与5.00MB。幅度小且样本有限，不保证其他输入、硬件或完整问答的速度。

最终来源构建另以四个新会话核对单槽/四槽与1024/2048维组合：全部输出和失败位匹配独立 RTX2060 整数参考，双方闭账一致，正常清理通过。首次权重读取回调抛出异常时，新 GPU 份额缓冲完成关闭，擦除和释放各453120816字节；双方保留材料全部烧毁。

矩阵三形状、七次 SiLU 及两个矩阵 GPU 对象同时存活时的异常清理来自前一组合构建。最终来源构建仅改变 Token 相关实现及构建配置，相应矩阵/SiLU来源经身份比对未变；不将前一组合结果称为在新二进制上重新运行。数值条件仍需满足原 BFV 误差界和输入范围，有限运行不是通用安全认证。
