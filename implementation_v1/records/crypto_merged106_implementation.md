# BFV 有界输入块合并（native v1.0.6）

本阶段在已授权的多目标系数打包上实现最多19个输入块同态合并。模型/修订、固定预算、SEAL/BFV锁定参数、参与方及私有权重边界不变；原始返回尺度、只发c1、精确361/420/361位与60轮GC不变。完整R2仍关闭。本文是工程实现及有限诊断证据，不另定正式测试或验收规范。

依据为现行 `参数与接口.yaml` 的 BFV packing、linear_return、controlled_decode，CRY-003/004/005，DEC-014 授权，以及本包 ART-002 解析界。历史 v1.0.5 尚未跨输入块合并，其静态成本/源哈希保留为当时调用图口径；本阶段重新绑定最终模型接线和成本，不把正在编辑的图称为v1.0.5运行。

## 输入、布局与返回

新增 `SecureOps::private_linear_streamed(x, rows, fx, fw, server_weights)`：x是本方ring59加法份额，公开列数在[1,155648]；rows为正公开输出行数，fx/fw为公开尺度且和≤58。回调签名 `(input_begin, actual_columns, first_row, group_rows)`，仅S调用且必须返回 `group_rows × actual_columns` 的S私有ring59权重。既有matrix API只包装该回调，返回顺序与原始fX+fW尺度相同。

令K=ceil(cols/8192)、d=min(cols,8192)、s=2d−1、m≤min(floor(16384/s),floor(8192/d))。每块X在系数[0,d−1]，第r行反序权重放到[r*s,r*s+d−1]，目标r*s+d−1。因此消息卷积支持区间[r*s,(r+1)*s−1]，区间互不相交，最高非零消息系数至多m*s−1<16384，不发生负循环回绕。每块权重槽数m*d≤8192，中心提升权重L1≤8192*2^58=2^71。噪声本身可以回绕，仍由该L1界控制。

K>1时d恒8192、m=1、目标恒8191；尾块回调只给actual列，后端用新零多项式补全到8192。不同块目标相同才可以直接同层合并。C不读取权重、不调用回调、不接收完整返回密文。全部K份输入分别新鲜加密并只读缓存；其原始系数缓存上限29,884,416字节（28.5MiB），不包括乘积、累加器、NTT临时区、密钥和上下文，不能称作峰值内存。

每输出组依固定公开块序，从输入副本做固定完整NTT明文乘法；第一真实乘积初始化累加器，其余同层相加。S同时在ring59累加自己的各块dot。全部块处理完才抽样一次完整16384系数独立mask，减去其BFV嵌入，再加fresh Enc(0)。每个返回密文仍只有c1发给C；C本地只提取目标u，S持有目标c0，逐目标独立GC对象计算原精确舍入，C取得被mask保护的结果份额，S保留mask目标系数加自己的dot。不存在逐块或最终隐式floor。

## ART-002 扩展与隐私状态

原锁定CBD加密误差E0<8193，每个明文嵌入误差≤1/2。设L=2^71，则合并相位误差严格小于

\[
(8193+\tfrac12)\sum_{b=0}^{K-1}\|W_b\|_1+8193+\tfrac12
<B_K=8194(KL+1).
\]

同层模q加法没有额外舍入，最后一次mask和Enc(0)仅贡献一次常数项；此推导不要求块间噪声独立，不借用重构one-hot稀疏性缩小份额噪声界。K1回到原界。K19时B=367603174126021792369745922，2*t*B+1=423817604611625804982080960099786874654031873，仍严格小于实际360位q。构建/参数守卫不变，运行上下文使用B19做精确GMP不等式守卫；公开入口在BFV网络/材料前检查K≤19。故在原假设下，有界噪声导致的有限会话解码失败率仍为0，不扩展为整体安全认证。

每输入密文、每最终mask/Enc0、每目标GC都单独预留ledger操作；同层加法本身没有随机材料。每个GC新建delta/标签/哈希状态，独立IKNP流继续前进，不重置OT或复用材料。新增回调可能在输入传输后抛出，因此原生入口用catch保证协议阶段所有异常都abort_session并断开阻塞对端、永久烧毁材料；公开K20拒绝发生在进入协议前。独立审查指出并复核了这个异常边界修复。

## 确实运行的有限范围

独立 `native/build-merged106` 用nice15、ionice3、j1实际构建正式/开发库、上下文程序和两种probe。只使用CPU小型密码原语，未使用GPU，未跑模型。开发AF_UNIX双进程三例通过：3列3目标（78、0、−50）；8193列3目标（跨块抵消0、全零0、−14，尾块actual=1）；155648列K19单目标−1355。K20在网络前拒绝，C回调从未调用，S回调26次。共22输入密文、5返回密文、7目标GC，应用字节58,097,814，两个ledger均closed/burned；stderr为空。

另以新会话运行错误callback诊断：S返回错形状后抛出，C的等待被断开，两方session均inactive且ledger均aborted/burned。该诊断只验证这一个失败触发，不声称覆盖任意系统故障。开发输出重构仅存在独立合成probe中，生产库没有该诊断入口。

`prag_production_bfv_merged_probe fresh-prefix pki-dir`链接正式库并强制mTLS、isolated_development=false。根端以`tools/run_bfv_tls_probe.py --target prag_production_bfv_merged_probe --record crypto_merged106_mtls_run.json`重编后单独记录实际mTLS证据；开发AF_UNIX结果不冒充mTLS结果。当前实际执行状态与哈希以同名JSON及mTLS记录为准。完整Token路径和完整模型R2没有实际运行。

## 静态成本与登记

每目标仍67,625个AND、34个64KiB公开GC帧。明确帧子集每目标2,237,755字节（含独立GC初始化240字节），每返回c1为786,528，每输入密文为1,572,960。固定图现行token仅一次19块streamed调用，因此每位置token返回目标由19H降为H，输入仍19份；gamma仍逐坐标，普通project仍32行tile，没有虚算进一步优化。

`tools/build_crypto_cost.py`输出`crypto_static_cost_v1_0_6.json`；它是固定公开调用图的通信子集，排除GC输入OT、base OT/公钥、其他共享/布尔计算、TLS/TCP/心跳/管理和所有耗时，不能解释成实测性能或理论最优下界。对应非空查询：输入308,304,077份、返回密文542,468,096份、目标GC 1,112,580,096个，该子集共3,401,298,000,293,088字节（约3.401PB，十进制），仍不可据此直接开启完整R2。根端独立推导计数与脚本逐项一致；最初独立草算未计每目标240字节初始化，已更正后对齐。没有同条件旧/新版性能比较。

`tools/build_crypto_evidence.py --build-dir native/build-merged106 --output-dir records/bfv-v1.0.6-pending`形成待登记工件；实际生产库与mTLS源哈希核对后根端统一生成当前artifacts并同步规范。脚本不要求重建一次性探索目录的probe二进制，历史二进制哈希保存在实际run记录中。本任务不切换当前配置，不启用完整R2。
