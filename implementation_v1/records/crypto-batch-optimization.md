# 原生 v1.0.2：等价批量实现与公开成本

本阶段只细化既定 BFV/GC 实现与通信调度，不变更 BFV 参数、角色、系数打包、59位份额环、定点舍入或只向 C 交付被掩码目标系数的契约。实现位置是 `native/src/bfv.cpp`、`native/include/prag/gc_batch_channel.hpp` 与 `native/src/gc_batch_channel.cpp`。数值规则仍由上层固定，高层完整系统启用门仍关闭。这里没有另立正式测试/验收标准。

## 实现一：固定大小的半门表分块

同一受控解码电路仍有457505个AND门，361位相位和420位分子也未改变。SCI生成每个AND的两个128位表项后，适配器按原顺序收集到65536字节缓冲区；每2048个AND发送一个定长块，最后不足的块补公开零。接收方按同样公开数量取得224个块，逐32字节交给原HalfGateEva，末块多余字节必须为零。缓冲区的额外内存固定64 KiB，结束或析构时清理。

`begin(public_and_gates)`、`end()`校验精确门数；激活期间只接受32字节半门表，不接受混用角色、形状或超过公开总数的表。GC输入OT、S输入标签、初始化标签与输出permutation仍走原认证Channel；输入标签全部完成后才开始表批次，全部表送出后才发送输出解读信息。因而没有将秘密数据写入公共头，没有依秘密控制批次大小，也没有让两方等待未发送的尾块。96字节Channel头继续绑定session/configuration/stage/operation/方向sequence。

表的原始有效载荷14640160字节、公共尾补零39904字节，加224个96字节头，共14701568字节；旧逐门帧为58560640字节。此改变只合并连续消息，门表、标签、计算拓扑和解码输出语义不变。半门表以外的原生消息暂未统一64 KiB分块。

## 实现二：同一输入块的密文复用

`private_linear(x, W, rows, fX, fW)` 将公开循环改为输入块在外、输出行在内。C每个8192槽输入块只加密/传输一次；S保留这个不可变密文，每个输出行复制后执行完整权重NTT乘法、全多项式掩码减法、独立新鲜Enc(0)与独立受控GC解码。每个输出累计各块返回的环份额，保持原始fX+fW尺度，仍由上层统一截断。

输入密文复用限于这一次函数调用的同一公开输入块，不跨会话保存或恢复。输入加密单独先登记`bfv_input_encryption`，每个输出仍单独登记`bfv_mask_Enc0_GC`。各输出所依赖的输入噪声相关，但每次的确定性解码误差界均不变，原证明的有限并集为0不依赖事件独立。

这不是把随机数再次用于一次新加密：C只生成一个输入密文，S对该已发送对象执行多次允许的明文线性运算。双方原本就知道这些行使用同一输入；不增加公开形状信息。S的私有W仍只在S本地，C收到的每行c1都经过独立重随机化，c0仍不发送。这里给出的是工程等价与既定隐私边界说明，没有因此宣称完成组合协议的独立安全证明。

**明确拒绝复用同一个Enc(0)。** 若两行共享同一个零密文，返回的c1差分会消去该随机项，形成 `(W_i-W_j)·c1_input`；在可逆情况下会暴露权重差。全环输出掩码只改c0，不能修复c1的这种泄漏。因此当前实现仍对每个返回调用一次 `enc->encrypt_zero`；将独立生成的零密文预先成池可作为后续调度细化，但必须逐项登记/独立消费，本阶段未实现该池。

## 实际核对与成本范围

独立公开合成入口链接真正的生产`prag_crypto`，`isolated_development=false`，双进程使用TLS1.3 mTLS；秘密重构诊断仍只在独立开发可执行文件。非零/全零两行、3列和8193列两种公开形状均已运行成功。8193列覆盖两个输入块、固定末块补零、跨块环求和及多个输出，负输入和负权重也包含其中。GC尾块的39904字节公共padding在每次解码中实际经过检查。实际结果与代码/静态库哈希见 `crypto-batch-debug-run.json`；这些样例不能推导任意软件输入或全模型都正确。

3列样例应用计算帧计量从169316739降到80025635字节，差值恰为两次GC表帧节省加一次输入密文节省。8193列样例为113159001字节。字节数每个传输方向只计一次，不含TLS记录与操作系统链路开销；没有据此推断网络吞吐或运行时间。

`tools/build_crypto_cost.py` 对当前高层32行投影tile、逐标量gamma、19块Token查表重算公开调用数量，并写入 `crypto_static_cost_v1_0_2.json`。完整非空query仍有1162678272次受控返回，GC AND总数没有下降。仅已计入的BFV消息子集，单资料257槽准备至少2085189971846944字节，完整query至少18499630136753376字节，即约2.09 PB和18.50 PB（十进制）。相比旧实现的7.95 PB/70.84 PB下降，但仍不支持在本机直接启动全模型R2。该下界不包含输入OT、其余秘密算子、TLS、心跳、磁盘或时间，不能当作完整通信总量。

余下方向是公开批量调用/点积布局及精确受控解码电路的进一步等价优化；必须重新核对跨输出系数污染、输出选择、独立随机量消费与整数界。当前实现没有做旋转、BatchEncoder、密文乘密文或改用近似解码，没有改模型或固定预算来回避成本。
