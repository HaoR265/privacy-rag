# CUDA R1 数值实现独立静态复核

结论：对当前 `r1_cuda_numeric.py` / `r1_cuda_model.py` 的模型调用路径，结合已冻结 coordinated numeric profile、真实权重登记及既有全行 L1 证据，未发现新的确定数值语义缺陷。本次不修改源码，不运行 CPU/GPU 模型、算子或编译；对应源文件与输入工件哈希见同名 JSON。此结论不是完整 CUDA 模型的运行结果。

## FP64 GEMM 与高低位重组

FP64 的使用条件是每个整数乘积及任意加法部分和均严格小于 `2^52`，操作数也在此范围内。于是整数转换、乘法和任意重排的逐项加法/FMA 均精确。代码的“转 int64 再转回 FP64 等于原结果”只是诊断，不能独立证明正确性；真正依据是各调用者提供的绝对项和界。

已沿所有当前调用检查此依据：普通线性及词表头使用 `maxabs(X) * max_row_L1(W)`；QK 使用 `d * maxabs(Q) * maxabs(K)`；PV 先确认 `P>=0`、`P<=F`、`sum(P)<4F`，再使用 `4F*maxabs(V)`。这里右侧转置权重的列 L1 就是登记的原权重行 L1。当前 QK 上界本身小于 `2^52`，PV 上界至多 `2^49`。

较大 down 点积采用 `x = 2^16*high + low`，其中带符号右移给出 `high=floor(x/2^16)`，`0<=low<2^16`；负数分解也成立。分别计算两个有界 FP64 点积，再通过 CUDA int64 左移与相加精确重组，没有在两个部分之间做 floor 或 rescale。代码先验证 `(high_bound<<16)+low_bound<2^56`，这同时保护重组的移位值与任意最终加法。

对于锁定的 `|x|<=2^34`，全范围可取 `|high|<=2^18`、`low<=65535`。两个模型实际登记的最大 down L1 给出：

| 模型 | 最大 down L1 | high 点积绝对界 | low 点积绝对界 | 重组绝对界 |
|---|---:|---:|---:|---:|
| Embedding | 2,136,368 | 560,036,052,992 | 140,006,876,880 | 36,702,662,775,760,592 |
| Generation | 2,160,211 | 566,286,352,384 | 141,569,427,885 | 37,112,283,959,265,709 |

两部分均小于 `2^52`，重组均小于 `2^56=72,057,594,037,927,936`。以上是公开登记值的整数推导，不是执行模型得到的数值。

## 平方和饱和树、floor 与非线性

坐标先检查、越界先置零，然后平方。对非负平方项，树上每个节点等于 `min(对应子树的精确和,L+1)`；这是由 `min(min(a,L+1)+min(b,L+1),L+1)=min(a+b,L+1)` 归纳得到的。最终 `total>L` 等价于安全坐标的完整平方和大于 L，也等价于原逐项 remaining-budget 扫描至少一次置位 over。两者最终的 row_bad、合法行精确和、失败行整行与和归零相同；坐标失败保持独立 OR，既有全局 failure 不会错误重置另一合法行。

每个树加法实际输入至多 L+1，未饱和相加至多 `2*(L+1)`；当前最大的 d=2048 RMS 域中此值为 `18,014,398,509,416,448<2^56`。坐标平方在此之前已通过乘法界检查。RMS 坏行使用 A=F，正常行 floor(sum/d)+16；L2 invalid/zero 行使用 A=F 与零向量、仅坐标/平方和异常增添数值失败，符合旧 R1/R2 已定语义。

所有固定正位移使用带符号整数右移，对负数给出 floor；指数变换的左移在运算前检查逐元素绝对界，`torch.where` 两个候选分支都采用非负安全位移数。NR 的状态检查、替代值 F/2、六轮顺序及各个 floor 均与旧 R1 相同。利用每轮状态 `0<=Y<=2F`，逆平方根的粗乘法界最大为 `26F^2<2^56`，RMS 归一化 B 与状态相乘的粗界为 `192F^2<2^56`。因此没有把已失败状态继续无界相乘。

Softmax 的无效行与无可见 key 行均保留原 dummy-key 替代，分母最多 1280F；减最大值在当前 QK 尺度下不会越过 `2^56`。公开 max 哨兵只用于比较，不会作为有效最大值进入 exp。exp 的三张表、两次 floor、负域失败与超过 32 尾部归零均一致。reciprocal 与 SiLU 的操作顺序一致；SiLU 仍按保守 sigmoid<=2F 保护原始乘法，之后检查 main 域。PV 的质量上界涵盖正常及异常替代分支，归约前的检查保持原 R1 的辅助诊断性质。

## 工件身份、int16 缓存和模型连接

本次只读核对两个量化 manifest 与 profile 的哈希、模型修订，以及全部 394 项矩阵登记的文件 SHA、形状、行 L1 和最大绝对权重元数据，均一致。这里没有重读数 GB 权重重做全量扫描；真实最大值与 L1 来自先前已登记扫描，运行时 loader 对实际读取文件重新检查 SHA。

两模型各 197 个矩阵的登记最大绝对权重均不超过 32767；整体最大为 6560。loader 在核对实际文件 SHA、域标记、登记 SHA 和形状后才在 CUDA 上窄化成 int16，故当前矩阵缓存无损。gamma 向量不进入该窄化分支。模型运算入口把缓存值精确恢复为 int64。此论证按本地已登记工件保持不变的条件成立，不覆盖另一个进程在文件校验与读取之间恶意修改工件的情形。

检查了普通投影的 main 输入域、down 的 `2^34` 输入和独立残差输出域、Q/K RMS/RoPE 专用界、raw QK/floor12/attention f20/floor20、PV floor24、SwiGLU floor12、残差相加后检查和下一次 RMS。最后有效位置是唯一 one-hot 选择；generation 的 1024 prefill + 255 次 decode 与 256 输出槽、EOS 后 dummy token 和掩码、KV 的公开写入位置均保持旧 R1 连接。失败位最后控制所有生成输出，不因提前 EOS 缩短固定循环。

`resource_policy.py` 强制实际 RTX 2060 CUDA 设备并拒绝 CPU 后备；本实现中 host 文件拷贝和公开标量界判断不是 host 上的 Transformer 张量算术。

## floorlog2 显存修正的有界跟进

根代理报告：采用旧 57 倍广播版本的完整 GPU R1 首轮在生成 prefill 第 7 层出现 OOM。models 已把 `_log2_floor` 替换为固定 `(32,16,8,4,2,1)` 六级整数分解。本次只审查这项替换，没有扩大模型审查或运行 CUDA。将新函数正文精确替换回旧函数后，整个文件 SHA 恢复为上一审查的 `a72039964107908dc3109fb250ba100b404443c2afeb0601ccd919098d4cbc9c`，因此确认相对于该静态快照仅这一个函数变化。新源码 SHA 为 `0fa528ec4da5806d6e587341994d5101cc313f1091bb6008bce08e7b5f1653c9`。

对正整数，每步检查 remaining 是否至少为 `2^shift`；若是，就将指数增加 shift，并把 remaining 右移 shift。六个 shift 覆盖整数指数的六个二进制位，因此最后指数为精确 `floor(log2(x))`。循环最大总位移为 63，没有左移或乘大数；指数也不超过 63。零与负值每次条件都为假，末尾显式返回 -1，与旧函数一致。

已执行 172 个极小纯 Python 整数断言，覆盖负 int64 边界、负数、零、所有 `k=0..56` 的 `2^k-1`、`2^k`、`2^k+1`，以及 `2^57-1`，均同时符合旧函数和正整数 `bit_length()-1`。另 4 个正 int64 高位例也符合数学 floorlog2。对于 `x>=2^57`，旧函数因阈值表终止于 56 而返回 56，新函数继续给出数学 floorlog2；这不是当前调用域的变化，因为 RMS/L2 和 reciprocal 已守卫的输入都低于此范围。

显存结论限于该核心：原广播产生 `[...,57]` 形状，即按位宽 W 表示为 O(NW) 工作空间；新函数的比较、右移、where 和指数更新都保持原 N 元素形状，以六次固定操作换成 O(N) 工作空间。对于 `[1024,6144]`，单个 int64 原形状张量为 48 MiB，布尔张量为 6 MiB；原 57 倍布尔张量为 342 MiB，若归约后端另物化同形状 int64 转换，其大小为 2736 MiB。新实现不再请求这种扩展维度，但仍有多个原形状临时张量，CUDA 缓存分配器、全模型缓存和其他算子也占显存，故不能据此宣称完整模型不会再次 OOM。

上述断言只运行标量 Python 整数翻译，不是新的 CUDA 核心实测。旧版本运行到第 7 层的记录不能算作新版本的运行验证；新核心的实际小 GPU 核对与后续完整模型核对由 models 分别记录。
