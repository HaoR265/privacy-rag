# 仅供讨论的 SwiGLU joint 局部域候选

状态：`PROPOSED_FOR_DISCUSSION_NOT_APPLIED`。本文件没有修改MLP、R1、R2或规范。它针对Q/K局部修订之后发现的第2层SwiGLU域失败提出可审查候选，不把本轮Q/K授权解释为对后续域变化的授权。

候选只扩大 `joint = floor12(SiLU(gate) × up)` 及紧随其后的 `down_proj` 输入域。`gate`、`up`、SiLU输出、down_proj输出、残差及其他主干仍保留256，所有尺度和截断顺序不变。候选joint实数绝对界为65536，对应f12整数268435456（2^28）。

此数值来自已有上游域而非本次观测最大值。当前路径已对SiLU输出和up分别执行abs≤256的检查，故二者f12整数A、B均满足|A|,|B|≤2^20。完整逐元素乘积满足|AB|≤2^40；因为两端界都可被2^12整除，按规范执行floor(AB/2^12)后严格落在[-2^28,2^28]，包括负数floor情况。原始乘法界2^40远小于2^56。

若继续沿用“每个权重也只知道≤256”的通用最坏界，6144维down_proj的原始累加确实可能超过2^56。因此候选绑定锁定量化权重的实际完整行L1界，而不删除预算检查。脚本 `model_tools/derive_swiglu_domain_candidate.py` 已逐文件核对SHA-256并重新读取两个模型全部56个down_proj的全部量化值，逐行计算 `L1_r = sum_j |W_rj|`；每个结果与既有量化manifest一致。

对任一输出行r，以及任意列子集或前缀J，有：

`|sum_{j in J} X_j W_rj| ≤ 2^28 sum_{j in J}|W_rj| ≤ 2^28 L1_r`。

以上都是秘密共享所代表的有符号数学值的界，不是单方随机份额的界；单方份额始终可取完整ring59，份额本地模运算回绕属于协议语义。该界覆盖完整数学点积、任何列分块的贡献，以及按任意固定顺序累加的数学部分和。两模型的最坏行结果如下：

| 模型 | 真实最大行L1（f12整数） | 原始完整点积/任意部分和f24整数界 | 2^56相对此界的倍数 |
| --- | ---: | ---: | ---: |
| Embedding | 2136368 | 573476918263808 | 125.65 |
| Generation | 2160211 | 579877224841216 | 124.26 |

两者均严格小于2^56=72057594037927936。JSON还逐层记录了形状、最大单个权重、最大行L1及行号、文件hash、完整点积界，并独立核对了更宽松的“维数×实际最大单个权重×joint界”也低于2^56。没有仅依赖一次公开输入的值域观察。

当前原生线性核按8192列容量分块、零填充，并按32输出行分批。Embedding的down_proj为3072列，Generation为6144列，均只占一个8192列块；32行分批不拆开单行点积。由上式可知即使后续选择更小的固定列块，只要先累加所有原始f24贡献、最后只做一次floor12，仍保持相同整数语义和预算。禁止在每个块后先截断再求和。本候选不要求新分块调度。

当前BFV接口本就处理完整ring59加法份额；既有条件噪声工件使用完整centered ring59的权重系数支持集。本候选没有扩大该已使用的份额/权重支持集，没有更改多项式形状、明文模数、系数模数或解码路径。这里仅据已读实现及现有工件说明该算术变更没有要求调整密码参数；没有声称重新完成密码正确性或整体安全认证。JSON绑定所读取native源文件及BFV条件界工件的hash。

若讨论通过，实现应只允许down_proj接受新输入域，并将逐层已验证权重界与数值配置绑定。down_proj完整求和及floor12之后仍立即使用256输出域；残差同样保持原检查。还必须重新实际运行后续层及生成模型，不能从此次算术可行性推导宣称整个模型都会正常输出。当前MLP仍为256，没有应用本候选。
