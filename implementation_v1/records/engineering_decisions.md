# 已授权工程选择

这些选择由实施代理依 DEC-010 作出，不是用户逐项确认的新设计。工程选择保持角色、安全假设、模型修订、锁定密码参数与固定预算。用户已授权在有合理依据的范围内直接调整数值配置并修改机读规范原文；真实设计冲突与必须改变上述固定边界的事项仍需商讨。

用户另已明确授权 DEC-014：在上述固定边界不变的条件下，研究并实施有证明支撑的多目标系数打包与公开输入块同态合并，直接更新现行规范。具体步长、容量、返回顺序和合并上限仍是实施代理负责证明与核对的工程选择。既有BFV路径采用公开自适应分块、联合投影、私有对角OT及Token独立无环跨钥返回；普通与Token分别有噪声和精确解码依据。参数、角色、隐私与模型预算不变，输出重新分享，总值及数值尺度不变。算法由实施代理推导并核对，并非用户逐项批准的公式。完整R2继续未启用。

| 选择 | 理由与边界 |
| --- | --- |
| 新建 implementation_v1，Python 管理与 C++17 计算 | 保留全部已有资料；SEAL/SCI 原生依赖与固定整数语义适合 C++，身份/数据库/HPKE 采用成熟 Python 库 |
| Postgres 事务发布、不可变对象 sha256 文件、OS keystore | 原子可见性和版本快照便于维护；摘要不是来源认证，HPKE不替代mTLS身份 |
| HPKE binding 进入域分离 canonical info，AAD 空 | 锁定 cryptography49 HPKE API 的可用等价绑定；所有必需字段受认证，见 interface_delivery.json |
| dummy Token 0、736 槽已分配及 288 尾部无效槽 | 实际官方模板与两个正文预算核对；秘密有效位/位置保持固定物理布局 |
| int32 LE NPY 量化文件、逐层 mmap | f12 权重域可安全容纳于 int32；计算进入2^59时显式转环，减少6GB显存/主存压力 |
| BFV 权重用完整 RNS/NTT 固定路径 | 避免秘密零权重触发库的单项式优化；不改变既定系数打包语义 |
| BFV公开输出分组、多目标系数及最多19块同态合并 | 不重叠支撑区间保证点积系数独立；每块md≤8192保持L1界，19块噪声界及运行入口上限绑定。每最终组新完整掩码/Enc(0)，每tile新GC对象，OT流只前进；零权重保持同一调度 |
| 秘密Token查表固定one-hot155648位置、S端流式读取权重 | 将19次独立返回合为一次完整H维返回；避免分配H×155648转置表。回调仅S执行，按公开块与行组取权重，不按秘密Token跳读，不产生中间floor；进入密码阶段后回调失败中止双方并烧毁材料 |
| 96-byte native公开头、固定payload；Python JSON头另层 | SCI调用形状已公开，每帧核对会话/阶段/op/config/seq/长度；不得按秘密前导零压缩 |
| 30秒独立双向心跳使用两条额外mTLS连接 | 每个SSL对象只归一个I/O线程，保持模型计算期间心跳活跃；180秒失活，没有会话总时限 |
| sealed memfd作为同方scheduler→worker输入 | 临时问题和份额不落磁盘；它只是同方进程传递，不把两个参与方的份额收集起来 |
| 查询/释放固定失败、无自动重试或参考fallback | 维护新会话/新随机材料边界；启用条件不成立时明确拒绝 |
| 受理前随机session UUID、本人取消意图、原子claim | 公共取消可能先于排队受理抵达；已claim会话必须先回收worker/连接再释放全局槽，秘密数值失败不进入取消HTTP |
| 配置直接绑定实际tokenizer与全部公开模型配置 | 仅登记权重清单不能验证本地实际打开的tokenizer；生成时与锁定下载哈希核对，运行时按C/S所需范围核对 |
| 完整模型只使用 RTX2060，禁止 CPU 回退 | 用户明确要求；R0/R1 在载入权重前检查 CUDA，GPU 不可用时拒绝启动。主机仅负责文件读写、分词、调度等，不再执行完整模型矩阵推理；R2 密码库是否支持 GPU 需独立核实，不能把参考 CUDA 当作密码后端 |

活动版本 `v1-f12-coordinated-20261013` 已接入 R1 与 R2 源码，规范直接维护当前定义。普通域2048、joint/down输入4194304、down输出和残差的分模型坐标界来自已核对的模型观测、全部真实矩阵行L1与原 RMS 指数预算的结合；不是仅用观测最大值挑一个阈值。每次平方及累加前用秘密检查保证安全，并对整行失败先替代再进入 NR。完整模型实际运行证据独立记录，不从范围推导直接宣称所有输入成功。

S侧原生注册对394个实际矩阵核对编译头绑定的文件SHA-256与每行真实整数L1，缓存已核对的只读映射。C只持有相同公开形状与范围元数据。矩阵调用同时检查输入域与行L1乘积严格小于2^56，让无回绕前提进入加载和调用路径；公开自适应BFV分块只改变传输与本地累加布局，完整点积在全部累加后floor12一次。此选择由实施代理作出，不是用户逐项指定的实现细节。

完整模型关闭条件由单独编译单元提供，避免编译器在主程序中把所有受门禁保护的模型路径作为常量死代码删除。当前仍固定返回关闭，不能用参数或环境变量绕过；完整模型路径可实际编译和链接，不代表已执行。

原生v1.0.3公开小表实现采用一次A2B、固定one-hot树与批量B2A，保持秘密index和固定调用形状；锁定SCI适配器统一公开1024项分块，解决扩展OT两端内部分块不同的严格帧问题，不改上游提交或协议。21项查表和跨1024项的18组真实乘法已核对。原生库/证据清单已形成，与全模型未运行的状态分开记录。

RTX2060 的 CUDA UVM 故障已用普通 `rmmod nvidia_uvm` 与 `modprobe nvidia_uvm` 修复，实际 `cuInit(0)=0`，小规模 GPU FP64/int64 算术通过；见 `records/cuda_environment.json` 和 `records/cuda_uvm_recovery_run.json`。操作前核实无其他 UVM 持有者，KDE 监视服务已恢复；OBS 和 KWin 原进程保留，按用户选择保留 NVIDIA DP 外屏输出。KWin 主合成和 OBS OpenGL 原本就在 AMD 上，无需重启桌面。没有执行 PCI 解绑、基础 NVIDIA/显示模块卸载或 GPU 重置。硬件修复与 CUDA 整数参考后端分别验证，不将设备核对记作完整模型成功。


## 当前协议 v1.0.11

- 用户已明确同意DEC-015：增加BFV矩阵三元组预处理并直接修改机读规范原文。具体随机矩阵转置、公开分块、描述符和RAII清理为实施代理选择；不是用户逐项指定公式。
- 批量GC、平方和守卫树及LUT one-hot树属于相同数值程序的等值实现：保留环、域、floor、六NR及固定消息形状。新鲜输出掩码使主机只接收份额；GC线内加合不等于明文重构。
