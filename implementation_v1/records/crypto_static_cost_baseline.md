# 当前标量 R2 的公开 shape 静态成本下界

这是对 `crypto_static_cost_baseline.json` 所绑定源码（原生 v1.0.1、批量优化前）的整数计数，不是运行测速、性能预测、密码方案的理论最优下界或验收标准。N>0 的完整query包括160槽Embedding、1024槽生成prefill、固定255个单Token后续forward以及256次logits；秘密EOS或数值失败不缩短这些公开循环。N=0另走公开空集处理，不适用本计数。

## BFV受控返回次数

当前 private_linear 对每个输出行和每个8192输入块执行一次受控返回；所有模型投影内积长度≤8192。Token秘密查表每Token固定19块，每块返回hidden个系数；RMS私有gamma目前逐坐标调用单输出BFV。记H=hidden、Ff=FFN宽度，则每层每Token返回数为 `4H + 7168 + 2Ff`：两次主干RMS gamma为2H，O/down投影为2H，Q/K/V投影为4096，Q/K逐头RMS gamma为3072，gate/up为2Ff。加Token查表19H及末RMS H，每Token为 `20H + 28(4H+7168+2Ff)`。

| 路径 | BFV受控返回次数 |
|---|---:|
| Embedding 每Token | 507904 |
| Generation forward 每Token | 815104 |
| 单资料准备，257槽Embedding | 130531328 |
| 查询Embedding，160槽 | 81264640 |
| 生成forward，1024+255=1279槽 | 1042518016 |
| 生成logits，256×151936行 | 38895616 |
| 生成合计 | 1081413632 |
| 非空完整query，不含资料准备 | 1162678272 |

这里数的是受控返回，不把“一个矩阵接口调用”当作“一次密码运算”。很多RMS单输出调用仍填充8192系数；这正是实际代码当前成本的一部分。

## 每次返回的明确通信子集

实际第一数据层有6个模数、n=16384；C输入密文两个分量，S返回c1一个分量，每条Channel帧有96字节头。GC相位宽度w=361、分子宽度r=420。固定电路的AND数为

`2w + 2w + w + 2r + r(2w+w) = 457505`。

分别对应相位加法、减q、mux、分子加法，以及420轮长除试减与mux。SCI HalfGateGen的每个AND实际发送两个128位标签，即32字节表；本版本每次send_block又加96字节头，没有对公共常量门作省略。

| 已计入部分 | 字节 |
|---|---:|
| 输入BFV密文及其帧头 | 1572960 |
| 返回c1及其帧头 | 786528 |
| 457505个AND表及逐门帧头 | 58560640 |
| S输入361个标签及帧头 | 5872 |
| C最终59位permutation及帧头 | 155 |
| 每个返回上述子集合计 | 60926155 |

尚未计GC输入OT、base OT、公钥/会话设置、其他算子、TLS/TCP/IP、心跳、管理、文件I/O等，因此是当前代码的保守通信下界。按每个方向实际传输字节计一次，不再重复相加收发双方的计量。

- 单资料准备仅这些BFV部分至少 `7952771922083840` 字节，约 **7.95 PB**（十进制）。
- 非空完整query仅这些BFV部分至少 `70837516615004160` 字节，约 **70.84 PB**（十进制）。

## 另一独立子集：QK与PV的MulShared

每个head的每对query/key有128个QK和128个PV共享乘法。两模型各28层、16个Q头。生成公开query/key对数为 `1024² + sum(1025..1279)=1342336`，未来causal或失效键目前仍实际计算后mask。

- 查询Embedding的QK/PV共 `2936012800` 个标量MulShared。
- Generation的QK/PV共 `153949831168` 个标量MulShared。
- 完整query该子集共 `156885843968` 个标量MulShared。

每个标量MulShared仅两方向被Beaver掩码的开口消息就有 `2×(16+96)=224` 字节；仅这部分另有 `35142429048832` 字节，约35.14 TB。未计该乘法的118个交叉OT、A2B/B2A、范围检查及其他乘法。检索精确/粗糙点积与两条证据全表gather另明确产生至少 `3072N` 个共享乘法，排序/范围检查/Select尚未计入。这里不宣称已数尽所有算子。

## 实际安排含义

当前原型不能直接对完整模型启动R2并期待可用的资源消耗；这项结论来自确定的消息数量，与RTX2060是否可用于其他计算无关。优化应保持既定角色、参数、隐私与数值语义，优先消除逐门帧头、同packed input的重复加密传输，并进一步研究精确受控解码和线性多输出布局。该下界绑定当前实现，不宣称等价优化后的实现仍有同样下界，也不以资源瓶颈为由换模型、位宽、预算或降低隐私。
