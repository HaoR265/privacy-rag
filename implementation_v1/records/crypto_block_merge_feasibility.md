# 19 块 Token 查表同态合并：有界可行性与接线方案

状态：仅分析，尚未实现、编译或运行该路径。本记录由独立集成审查代理读取当前 `compute/model.hpp`、`native/src/bfv.cpp`、`native/include/prag/secure_ops.hpp`、ART-002 及机读规范后形成；没有运行模型或协议。仅做了下列公开整数界及计数的 Python 整数核算。这不是正式测试规范、安全认证或完整 R2 运行证据。

本分析接受已批准的有证明支撑的分块合并；不重复正在实施的 v1.0.5 多目标系数布局证明。以下将其每个输入块的既有前提视为接口条件：固定数据层、每个乘法权重多项式至多 8192 个非零中心系数、单个点积宽度至多 8192、目标系数布局公开且无回绕污染。Token 块宽 8192，因此每个返回多项式仍只含一个目标；合并的收益来自减少输入块之间的返回次数。

## 结论与真实入口

在固定第一数据层上，对最多 19 个同形状输入块分别作密文×私有明文多项式乘法，将结果仅在 S 本地作密文相加，最后才执行一次完整新掩码、一次新鲜 Enc(0) 和一次目标受控解码，可以保持原来的模 2^59 结果、数值尺度和双方输出边界。实际 q 对放大后的解析噪声界仍有充足余量。

但只修改当前通用 `SecureOps::private_linear` 不会改善 Token 入口。`Transformer::token` 现在有 19 次独立、各 8192 维的 `private_linear(onehot,w,H,0,12)` 调用，随后本地相加；后端每次只看到 K=1。必须把 Token 的 19 块接入同一次有界流式调用。当前通用 private_linear 接受任意长度 x，也不能把 K≤19 的证明直接声称覆盖其所有合法输入。

建议采用根代理提出的路径：公开限制 `1 <= cols <= 19*8192`；输入一次提供 19×8192 个共享 one-hot；保存每块的一份输入密文；然后按输出组处理，S 通过公开索引的权重回调逐块读取 `table.at`，每个输出组先累加所有块乘积，再执行受保护返回。C 永远不调用权重回调。已有矩阵参数入口可包装同一实现，保留公共尺度参数及认证、会话检查。

## 环语义、尺度与索引

记 t=2^59，K≤19，统一块宽 d=8192，H=1024 或 2048。对于输出坐标 h，令块 b 的多项式为

\[
X_{C,b}(z)=\sum_{j=0}^{d-1}x_{C,b,j}z^j,\qquad
W_{b,h}(z)=\sum_{j=0}^{d-1}w_{b,h,j}z^{d-1-j}.
\]

各项乘积次数至多 2d−2=16382<n=16384。同态相加不改变指数，所有块的目标必须一致为 d−1=8191。S 形成 `A_h = sum_b Enc(X_C,b) * W_b,h`，然后 `A'_h=A_h−R_h+Enc(0)`。受控解码仅向 C 给出

\[
y_{C,h}=\big(\sum_{b,j} w_{b,h,j}x_{C,b,j}-R_h[8191]\big)\bmod t,
\]

S 的份额为

\[
y_{S,h}=\big(\sum_{b,j}w_{b,h,j}x_{S,b,j}+R_h[8191]\big)\bmod t.
\]

双方相加恰好是原来 19 块原始结果份额之和。环中换代表引入的 t 的整数倍在理想 BFV 相位中恰好对应 q 的整数倍，因此不要求单方随机输入份额或随机掩码在模型数值域内。

Token 的 one-hot 保持 f0，私有 Token 表保持 f12，输出仍为 f12；不能添加 floor12，不能在各块内部截断。合法 Token 或按现有秘密规则替换成 0 的非法 Token 恰有一个有效 one-hot 项，故重构语义结果是一行 Token 权重，其坐标绝对值至多 2^20（real 256 的 f12 整数）。各块重构语义部分和同样至多一行权重，未因合并而扩大到 19 倍。该事实不限制单方随机份额，也不替代通用投影已有的完整及任意部分和 `<2^56` 证明。现有输出主干范围检查及失败位保留。

最后块真实 Token 行数仍分别是 4213 和 4480；物理输入与权重块都保留 8192 宽。若把末块缩为 actual 并将目标换成 actual−1，然后直接与前面块密文相加，会把不同系数当成同一个点积，结果错误。流式入口必须统一 d、stride 和目标索引；对长输入尾部作公开零填充。不要改动现有 one-hot 秘密失败处理、所有位置扫描或固定 Token 数量。

通用调用如果 `cols<=8192`，d=cols、K=1，可继续采用 v1.0.5 的公开多目标布局。只要 K>1 就取 d=8192，此时每密文目标容量 m=1；本方案不会把不等宽尾块与多目标布局混用。

## K≤19 的解析噪声界

继承 ART-002 的锁定 SEAL CBD、ternary s/u、一次 key→first-data 降模、之后不降模等条件。初始零密文相位误差严格小于 E0=8193；明文缩放嵌入的舍入误差每系数至多 1/2。每个块的中心权重多项式 L1 上界为

\[
L=8192\cdot2^{58}=2361183241434822606848.
\]

K 次乘法相位相加，再减去一次缩放 R、加入一次独立零密文时，最终每个系数相对于理想缩放明文的圆周误差严格小于

\[
(8193+1/2)\sum_{b=0}^{K-1}\|W_b\|_1+1/2+8193
\;<\; B_K=8194(KL+1).
\]

同层 BFV 密文相加只作精确模 q 系数加法，不增加舍入误差。不同输入密文误差是否相关不影响三角不等式；同一输入密文跨输出组复用亦不影响这个确定性界。不要将“重构 one-hot 稀疏”用于压低密码噪声界：C/S 份额本身为环随机值，乘法必须由实际多项式 L1 控制。

严格满足 `2*t*B19+1 < q`；`floor(log2(q/(2*t*B19+1)))=211`。因此在 ART-002 原有条件及新增 K≤19 条件成立时，有界采样造成的解码失败概率仍为 0，任意有限会话的相应并集也为 0。不是软件正确性概率、安全优势或硬件故障界。

受控解码仍先把各方分量作精确 CRT，再在 GC 中得到规范代表 `0<=v<q`。所以分子依旧是 `v*2^59+floor(q/2)`，仍小于 `q*2^60`；361/420/361 位宽及固定 60 轮除法均不需要改动。不能仅因为最终模 t 结果短小就缩窄 CRT 或 GC。

当前 ART-002 的“每个返回只一次明文乘法”和 `B=8194*(L+1)` 前提不覆盖该新路径，虽然 q 很大也不能沿用旧登记。实施必须直接更新证明、实际参数守卫和生成工件，登记 K_max=19、`B_K`、不改变降模层及最终一次保护的条件，并同步当前配置哈希。原有参数本身无需改变。

## 流式实现的具体边界

1. 在网络或大内存分配之前检查公开形状、rows>0、cols>0、cols≤155648、`fx/fw/fx+fw≤58`、身份与会话状态；用先上界检查再计算块数的方式避免 `cols+8191` 溢出。公开拒绝超界的通用调用，不能无声地套用 19 块证明。若将来要支持更长输入，另行按公开的最多 19 块分组返回并在环上相加，或形成新的解析边界；不要现在宣称无界支持。
2. 按块号固定顺序生成并发送 K 份输入密文。每份独立预留输入加密材料；第一数据层 parms_id、size=2、系数形态完全一致。缓存对象之后不可被原地乘权修改；每个输出组从它们的副本开始。
3. 每个公开输出组按 b=0…K−1 读入 S 私有权重、执行固定完整 lift/NTT 乘法，S 同时计算对应 `W_b*x_S,b` 的模 t 局部项。权重回调仅 S 调用；返回形状必须与公开 group_rows×d 一致。不能让私有零系数、秘密 one-hot 所在块或非法 Token 分支决定调用、乘法或发送次数。
4. 将同层 size=2、非 NTT 表示的块乘积用精确同态加法合并。以第一个实际乘积初始化累加器，避免把未初始化 Ciphertext 当作合法零密文。全零权重允许产生 S 本地透明中间对象，仍完整执行所有块及最终保护；任何未保护的块结果都不离开 S。
5. 所有块完成之后，才预留并采样一个覆盖 n=16384 全部系数的独立均匀 R，执行减 R，再添加一次独立新 Enc(0)。mask 不能只覆盖目标，不能跨输出组/Token/会话重复。若失败则终止并烧毁已预留材料，不重用缓存密文或 PRG 状态重试。
6. S 只发送这个最终密文的 c1，保留 c0；C 仅对公开目标坐标准备本地 `c1*sk` 的精确 CRT 值。每个目标分别预留新 GC，固定公开顺序执行。S 不收到 u，C 不收到 c0 或完整密文，非目标系数无输出。
7. ledger 仍使用已有会话/configuration 绑定与 fsync/O_EXCL 语义。每次合并调用有 K 次 `bfv_input_encryption`；每最终返回有一次全多项式 mask+Enc0 预留；每目标有一次 GC 预留。K−1 次相加本身不消耗新随机材料，但公开调度/阶段身份要绑定。异常、取消和关闭仍把所有已预留材料标为 burned。新调用布局必须进入配置版本，不能与旧“块→返回”序列在同一配置下混用。
8. `Transformer::token` 先形成全部 155648 个秘密 one-hot 算术份额，再以 rows=H、fx=0、fw=12 调用一次流式入口。不要在其外部沿用 `project` 的 32 行分片方式，否则每片又会重复 19 次输入加密。后端内部可以用输出组/行片限制临时权重内存，但必须共享本次调用的同一 19 份输入密文。

物理数据量（不含 SEAL 对象开销）：19 份输入密文共 `19*2*16384*6*8=29,884,416` 字节；完整 one-hot 份额数组 `19*8192*8=1,245,184` 字节。一个输出组的单个乘积/累加器约 1.5 MiB；Token 情况 m=1，无需 H 个大密文同时存在。一个 32×8192 的权重读片为 2 MiB，若回调每目标读一行则为 64 KiB。避免物化 H×155648 的 Word 矩阵：Embedding 需 1,275,068,416 字节、Generation 需 2,550,136,832 字节。输出组完全处理后即可释放临时数据，再开始下组。

## 静态收益及其限制

下面只计算 Token 私有表查找的 BFV 返回和 GC 部分，依据当前 v1.0.4 的固定帧下界：每个单目标最终返回 `3,024,043` 字节，含 c1 帧及固定 GC 表/标签/输出排列帧；每份输入密文帧 `1,572,960` 字节。GC 输入 OT、一次性 base OT/公钥、TLS/IP/心跳、秘密 one-hot 构造、其他模型算子及时间均不包含。v1.0.5 对 d=8192 仍是 m=1，所以该 Token 差额不依赖其短维度多目标打包的收益。

| 范围 | 旧返回/GC 次数 | 新返回/GC 次数 | 少发送的上述帧下界字节 |
|---|---:|---:|---:|
| 1 个 Embedding Token | 19,456 | 1,024 | 55,739,160,576 |
| 1 个 Generation Token | 38,912 | 2,048 | 111,478,321,152 |
| 257 Token 文档 Embedding | 5,000,192 | 263,168 | 14,324,964,268,032 |
| 160 Token 查询 Embedding | 3,112,960 | 163,840 | 8,918,265,692,160 |
| 1279 Token 生成前向 | 49,768,448 | 2,619,392 | 142,580,772,753,408 |

一次非空查询的查询 Embedding 加固定 1024 Prefill/255 Decode 共减少 50,098,176 次 Token BFV 返回/GC，少发送这些帧的下界为 151,499,038,445,568 字节，约 151.50 TB（十进制）。每 Token 的输入密文仍为 19 份，所有 19×H 次密文明文乘法仍执行；减少的是 `(19−1)*H` 次返回、掩码/Enc0 和 GC，增加 H×18 次本地密文加法。

仅 Token BFV 子路径在合并后，一次非空查询仍有 8,459,619,546,336 字节（约 8.46 TB）的上述帧下界，未计秘密 one-hot、OT 或任何其他模型算子。因此该优化可显著减少通信，不足以声称完整 R2 在当前机器上已经可运行或有实际耗时改善。现有原生后端仍为 CPU 密码原语，这项分析也没有形成用户要求的 RTX2060 私有模型后端；生产 GPU 能力守卫应继续关闭。

实施后的最小开发核对应针对新语义：公开小维度跨块、负权重/负环代表、跨两块抵消、全零权重、尾块统一目标、K=19 边界、超界公开拒绝、两方 ledger 新序列及生产库 mTLS 身份。这里仅列需要实际支撑的实现点，不宣称已运行，也不建立正式验收范围。
