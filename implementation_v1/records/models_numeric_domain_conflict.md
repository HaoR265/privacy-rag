# 已锁定模型与运行域的实际冲突

涉及 NUM-003、NUM-004、NUM-005、MOD-001、MOD-002。未更改任何受保护设计，也没有把安全替换后的输出当作正常答案。

公开合成问题“隐私计算如何保护问题？”经固定 tokenizer、完整指令与 EOS 后，实际使用 160 个物理槽。Embedding checkpoint 为已锁定 `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，全部 310 个量化张量自身均符合绝对值不超过 256。完整 R1 的 28 层执行结束后，秘密失败位的明文参考值为真，向量有效位为 0，输出零向量；这是失败处理生效，不是模型正常成功。

独立公开诊断把首个失败定位到第 0 层 `self_attn.k_norm` 之后、RoPE 之前。R1 的 f12 整数最小 -1939843、最大 1863704，即 [-473.59448, 455.00586]；同输入与真实浮点权重的 R0 同算子约为 [-472.98856, 454.99985]。超界包含有效问题位置；并非只由无效 dummy 槽引起。R0/R1 在该算子的最大差约 0.69662，远小于超出 256 的幅度，因此不能将冲突归因于几位 floor 误差。机器记录为 `models_numeric_domain_conflict.json`。

NUM-003 明确约束主干乘法输入，包括 Q/K 归一化后将进入 RoPE/注意力的值；NUM-004 要求先证明无回绕，不能回绕后再检查。现在的实现保持 256 的既定检查，按 NUM-005 将超界值安全替代并累计失败。因此这一数值配置不能被登记为实际正常可用，生产路径仍关闭。

不能看到约 473 就直接把全局域改成 512。256 是已锁定设计；改动还会改变各算子条件界，例如点积和平方和随输入域平方增长，RoPE 两项合并、残差、规范化缩放、NR 乘法和后续层都需重新核对。一个算子的一个公开输入上界不能代表全部输入、全部层、生成模型或完整查询都被覆盖。全局放大也可能使原 2^56 中间预算不再成立。

建议先取得用户对数值运行域设计调整的授权，再按算子区分 K/Q norm 输出、RoPE、注意力点积、残差和 MLP 所需的域，并重新推导每次乘积、完整累加与左移的界，同步 R1/R2、配置版本和工件。仍应保留秘密域检查及固定失败路径。此建议未生效；当前继续输入、存储、交付、协议组件及独立 R0 参考等不依赖这一正常数值域的工作，没有更换模型或削减预算。

上述运行是实现诊断，不构成新增正式测试内容、规模或验收规范；更不证明 R2 完整隐私链成功。
