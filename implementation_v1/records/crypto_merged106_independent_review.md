已复读异常边界修复，当前所读实现中没有遗留的确定缺陷，且与 K≤19 的证明前提相符：输入块来自相同上下文和会话密钥；逐块固定 NTT 明文乘法恢复为系数表示后精确同层相加；最后统一完整掩码和 Enc(0)；C 仅接收 c1 并逐目标使用原有精确解码。尚不能仅凭静态审查宣称实际协议已运行。

## 发现项：协议开始后的异常应使原生会话终止

初读版本在已生成/发送输入密文后，S 的权重回调抛异常或返回错形状，会直接向上传播，但原生 `SecureOps` 仍可保持 active，C 已等待最终 c1。生产 `compute/worker_main.cpp` 的外层 catch 会执行 abort，因此该 worker 有兜底；直接调用公开原生 API 的调用者若捕获异常，仍可能继续使用同一密码状态。

实现方已在公共形状检查之后、BFV 初始化之前设置 try/catch：协议主体的任何异常调用 `abort_session()` 后重新抛出。已复读确认该范围涵盖密钥初始化、输入加密、回调、形状检查、同态运算、结果返回与 GC。材料此前已持久预留，abort 关闭通道、将会话置为非 active，并记录 all_reserved=burned；网络前的公开形状拒绝仍为非终止拒绝。此项已从源码层面确认修复。

还阅读了新增 `dev_bfv_merged_probe.cpp`：独立 `--callback-failure` 模式使 S 回调返回错形状，要求 S 收到相应错误、C 解除阻塞且双方 session inactive；普通模式包含 K=1 矩阵兼容/多目标、8193 列跨块抵消与一列尾块、K=19，以及 K=20 在网络前拒绝。探针重构只在诊断可执行程序中。审查者没有执行该探针，实际运行结果需单独绑定。

独立公开整数预期为：K1 三行 [78,0,-50]；K2 三行 [0,0,-14]；K19 单行 -1355（ring59 为 576460752303422133）。K19 参考仅计算长度 101×17=1717 的一个周期及 1118 项尾部，完整周期乘积和为零；没有执行 BFV/GC。

## 正确性与源码对应

设 L=8192×2^58=2^71。每个输入加密相位相对于理想 q/t 缩放的逐系数误差严格小于 8193+1/2，故 K 个乘积相加、一次掩码和一次 Enc(0) 后的误差严格小于 (8193+1/2)Σ||W_b||₁+8193+1/2。选取统一整数界 B_K=8194×(K×2^71+1)，K≤19。

实际参数核算：B19=367603174126021792369745922；2×2^59×B19+1=423817604611625804982080960099786874654031873；分别为 89 和 149 位，严格小于实际 360 位 q。已用公开整数核对全部 K=1..19。`verify_art002_context` 使用同一 B19 表达式；公开入口把输入限制为 1..155648 列，内部再次限制输入/缓存块数为 1..19 且相等。

`dimension=min(8192,完整列数)` 固定于整次调用。K>1 的尾块仍 d=8192、目标 8191；`actual` 仅决定回调和本地读入的真实列数。每块新建的 SEAL Plaintext 自动初始化为零，只填写 actual 个位置，因此剩余权重为零。输入份额同样先零填充至 d。K=1 继续使用已证明的多目标系数布局，rows≤capacity 保证每块中心权重 L1≤2^71。

回调仅在 S 调用，参数是公开 begin/actual/first_row/group_rows，返回严格检查为 group_rows×actual。矩阵入口同步包装该回调，不改变 f_X+f_W 原始输出尺度。各输入密文缓存只读，乘法使用副本；首个真实乘积初始化累加器，不引入额外 Enc(0)。固定 forward NTT、逐点乘、inverse NTT 后，SEAL 同层 add 验证 parms_id 和 NTT 形态一致，并作精确模 q 加法，不增加缩放舍入。

输入加密逐块预留；所有块在 S 完成乘法后才预留每返回组完整掩码和 Enc(0)。C 没有块乘法，也按照同一下一操作编号预留后等待 c1。每个目标在创建新 GC 对象和消费 OT 前再次预留。每目标独立 delta/常量/hash seed 与持续前进的独立 IKNP 状态延续 v1.0.5；361/420/361 位宽及 60 轮精确解码不变。

## 实施者运行证据的只读核对

实施者通知构建、真实 AF_UNIX 两方探针及回调故障模式成功后，审查者读取了 `bfv_merged106_probe_run.json`、`bfv_merged106_callback_failure.json` 及两次运行的双方 ledger。三例实际记录与上述独立公开参考一致；正常运行记录共 22 次输入加密、5 次完整掩码/Enc(0)、7 次目标 GC，两方 ledger 相同且以 `terminal=closed all_reserved=burned` 结束。应用字节记录为 58097814。

故障记录中双方均为 `terminal=aborted all_reserved=burned`。C 比 S 多预留一次 mask 操作符合调度：C 可在 S 权重回调完成前预留并等候 c1，S 回调失败后直接中止，双方全部预留均烧毁。JSON 记录表示 C 已解除阻塞，源码故障模式同时要求双方 session inactive，主进程检查子进程退出状态。上述执行由实施者运行，审查者只读核对证据；这些记录是 isolated development 的 AF_UNIX 运行，不是生产 mTLS 运行或完整 R2。
