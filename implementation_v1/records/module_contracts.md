# 模块依赖与运行契约

活动数值版：`v1-f12-coordinated-20261013`。这里只登记实现接口及依赖，不制定正式测试或验收要求。所有尺度描述完整数值的解释，不是对单方随机份额的幅度限制。

实现依赖顺序为：规范/工件 → 固定输入与份额类型 → 密码原语/数值算子 → 私有模型 → 准备/交付/受保护存储 → 快照/私有检索/证据 → 固定生成/最终释放。管理、交付与密码原语可并行实现；完整模型的数值前提未成立时，其余已独立核对的模块仍可继续。

生产 `prag_worker` 链接真实密码库。早期独立开发探针另链接开发库；当前混合后端有限诊断链接正式密码库，外部oracle是另行编译的开发可执行文件/控制器，不进入生产库。`references/` 的R0/R1只能处理拥有方授权或公开开发输入，不被生产包导入。当前内部部分C++ Row/Word仍靠固定调用约定表达尺度；外层SharedVector/BoundRecord和worker ABI有实际形状、角色与配置检查，这不等于内部所有边界已完成强类型化。

完整参考模型执行另受本机资源限制：R0/R1 必须使用实际可分配、可计算的 RTX2060 CUDA 设备，禁止 CPU 模型推理与自动回退。模型权重可以由主机逐层读取并传入显存，模型算术须在设备上执行。`tools/check_cuda_environment.py` 只检查设备和极小算术，不读取 checkpoint，不是完整 R1 或 R2 正确性依据。CUDA UVM 已修复并通过实际设备核对；独立小整数算子参考不构成完整 CPU 模型的例外入口。

R2混合后端由CPU执行既有SEAL/SCI密码协议、RTX2060执行本方份额本地运算及KV存储。两方仍各持一份；硬件改变不改变允许泄漏、协议角色或模型预算。M3开发协调器在独立临时仓库中完成实际受理/原子claim；S计算结束先通过同方socket申请releasing并等数据库提交ACK，随后才做协议释放。双方退出后，S准备份额原子持久化并结束会话；D本地失败位不进入S数据库。query开发出口仅给外部oracle最终证据份额，未进入正式最终答案接口，不启用生产门。
