# CUDA 生命周期与运行身份修复复核

本轮仅复核上轮指出的清理和运行身份两项问题。当前代码已覆盖这两项缺口，所请求范围内未发现新增遗漏；没有运行模型或 CUDA，也没有修改源码、配置或 README。

- `pipeline.run_reference` 的 `try/finally` 覆盖准备失败的提前返回、查询、检索及生成异常；正常 E→G 路径仍在加载 G 前释放 E。
- `CUDAIntegerQwen.close()` 清空失败回调、权重、KV 缓存和进度回调，断开 `_begin()` 产生的模型回调引用环。
- 独立 Embedding 入口在构造成功后，计算、同步和记录写入均处于 `try/finally` 内，退出时调用 `close()` 并释放模型引用。
- 实际身份辅助模块是 `model_tools/reference_provenance.py`。它绑定入口脚本、自身、输入预处理、参考源码、数值 profile/常量/依据、模板、两模型量化清单及实际 tokenizer/config 文件；Embedding、算子和完整 R1 入口均记录运行前身份及运行后比较。
- 完整 R1 入口在计算前保存 `.start.json`，普通异常记录和正常结果都包含身份比较。比较结果为布尔字段；`false` 不能被解释成同一文件身份下的完成结果。

本轮只使用 Python 标准库进行 AST 解析和公开文件哈希核对，必需绑定项存在且核对期间文件身份不变。源码 SHA-256、核对位置和快照摘要保存在同名 JSON 中。

这不替代异常路径的实际显存观测。起止文件哈希核对也不是已导入字节码的运行时证明，不能检测两次捕获之间改动后又恢复的文件；冻结源码后再运行的约束仍然成立。本记录不增加完整模型、性能、隐私或 R2 正确性结论。
