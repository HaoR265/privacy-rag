## 读取与实施顺序

1. 读取本文件、目标背景及规范索引，掌握项目对象和当前范围。
2. 读取行为规范与代理规则，结合用户当次任务确定是否已授权实现。
3. 读取架构、参数接口和协议流程；实现一个模块时同时明确输入、输出、数据表示、参与方与固定执行次序。
4. 读取决策与工件，区分AI可自主决定的实施细节、尚未生成的文件和必须商讨的约束变化。未生成工件按依赖逐项形成，不能以空值直接启用，也不要求全部形成后才开始开发。

本规范提供实现约束。收到“开始实现”的任务后，可在已定语义内实现；仅收到文档任务时不自行启动代码、模型下载或部署。

## 约束语义

`MUST`为必须遵守，`MUST NOT`为禁止，`SHOULD`为可说明理由后偏离的建议。规则ID用于内部追溯，不是实现完成标记。Markdown和YAML共同表达相同约束，遇到冲突应报告具体规则ID或参数字段，不按文件格式任选结论。

用户明确的新决定须同步现行原文。DEC-004、DEC-010与DEC-013授权AI自主决定常规实施细节及合理范围内有依据的数值误差、范围和参数调整，无需逐项确认；同步规范、R1/R2及真实工件并记录依据。角色、安全假设、泄漏范围、模型修订、整数环、已锁定密码方案与规格、固定预算保持不变；超出授权或正确性前提无法成立时才商讨。按固定规格生成参数实例不属于修改规格。

## 文档自身检查

在本目录运行 `python3 校验规范.py`，依赖Python 3和PyYAML。脚本只读取本文件夹，不读取其他文档，不联网，不下载模型，也不运行模型或密码协议。

检查内容为YAML解析与重复键、入口文件、规则编号与正文、包内引用、文件链接及独立交付边界。同时核对已登记包内工件的文件存在性、JSON格式与SHA-256。返回成功只表示文档内部一致，不代表软件或协议已经验证。
