# 行为准则与编码规范

本文件规定实现代理的权限、代码语义和变更记录。用户已确认DEC-004权限边界，并通过DEC-010授权AI自主决定既定约束内的实施细节。收到实现任务后，代理按本包的已定约束工作；收到文档任务时，范围仍为文档。规范文件本身不构成启动实现或下载的任务指令。

## 基本准则

1. **先定位规格。** 实现每个模块时标注相关规则ID、输入输出形状/f/环/保密状态/版本；不以库函数名代替功能契约。
2. **保持数值语义。** R1与R2执行同一整数算法；floor、截断位置、并列规则、有效位和失败路径不能暗改。float参考误差不能解释R2/R1不一致。
3. **维持数据边界。** 普通API、日志、调试回退不得得到完整秘密；不得将S所缺的另一份额直发给S；结果释放仅走规定出口。
4. **区分公开与秘密控制。** 公开N=0、断连可分支；EOS、有效位、命中、秘密数值失败不得驱动公开分支、寻址或提前退出。
5. **管理随机材料。** 占用先于消费，状态不明作废；失败不恢复半途密码状态。不得以固定随机种子进入正常查询。
6. **版本可复现。** 固定源码提交、模型修订、配置与常量hash；真实文件未取得时写未生成，不填造hash或声称通过。
7. **调整可追溯。** 参数不达标先检查实现；改变公开精度/分块要更新全部参考及证据，改变角色/环/泄漏是架构变化。
8. **结果如实。** 不将设计、静态MAC估计、原型、小形状测试、实测完整系统混称；不挑换有利样例、不省略失败/离线成本。
9. **部署资源。** 管理Python、密码核心C++17。R0/R1明文模型必须在实际可用的RTX2060上执行，禁止CPU模型推理和回退。R2使用已实现并经实际核对的混合后端：RTX2060承担本方份额张量的本地运算、公开布局和KV份额存储；CPU执行SEAL/SCI的BFV、OT、GC和Beaver协议。两端传输仅限本方份额、S自有权重与公开参数，不得重构秘密或调用R1代替R2。GPU前提不足只关闭受影响路径；管理、编译及独立密码原语工作可继续。完整层、单Token Decode、私有检索和完整系统分别报告，不因局部成功开放生产整链。

## 编码约定

以下条款在用户批准的实现自主范围内制定，未改变密码功能定义。CODE-P01—P08 是本版工程要求（MUST）；CODE-P09 是风格建议（SHOULD）。具体类型名和实现方式可等价调整，相关安全与数值语义不可改变。机器条目见[代理规则](代理规则.yaml)。

| 编号 | 约定 |
| --- | --- |
| CODE-P01 | 通过显式类型区分Public值、ArithmeticShare、BooleanShare、SecretToken、PrivateWeight；API拒绝错误形状/尺度/版本，不能让调用者隐式转换。 |
| CODE-P02 | 将R0浮点参考、R1整数参考与R2生产运行入口分离；可重构秘密的辅助代码只能存在于独立受控入口，不能由生产配置开关打开。 |
| CODE-P03 | 环加减乘使用明确定义的无符号/足够宽整数操作；有符号解码单独实现，避免依赖C++有符号溢出或未定义移位。 |
| CODE-P04 | 公开错误使用结构化代码；秘密失败位由安全协议携带。不得把异常消息附上输入、份额、密钥、密文解密相位。 |
| CODE-P05 | 密钥/临时份额/一次性状态采用清晰所有权和生命周期；清理动作覆盖正常、失败、取消。具体安全擦除能力按库/系统实证，不因调用析构便宣称物理擦除保证。 |
| CODE-P06 | 依赖和格式工件版本锁定；包布局/帧格式有显式format_version、长度验证与确定性编码。未定的依赖版本不得伪称已锁定。 |
| CODE-P07 | 如实区分已定义、已实现和已核实的内容；没有实际依据时不得声称运行成功、隐私安全或性能达标。本条不指定测试项目、方法或通过门槛。 |
| CODE-P08 | PR/变更记录说明对应规则ID、修改前后行为、决策影响、实际完成的检查及其依据和剩余限制；未完成或未核实的内容明确标注。 |
